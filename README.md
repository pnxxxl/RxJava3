# Реактивная обработка данных поставщиков

Консольное приложение на Java 17 и RxJava 3. Модель `SupplierOffer` содержит поставщика, товар, цену и количество, как данные о товарах и поставках в BootcampLabs. Backend и база данных для этой практики не нужны.

## Запуск

```powershell
mvn clean package
java -jar target/supplier-reactive-processing-1.0.0-all.jar
java -jar target/supplier-reactive-processing-1.0.0-all.jar --backpressure
```

Последняя команда дополнительно запускает пример управления скоростью потока. Для проверки логики: `mvn test`.
Исходники используют UTF-8. Приложение выбирает кодировку текущей консоли; при перенаправлении вывода использует UTF-8.

## Что показывает программа

1. `Flowable` выдаёт начальные записи, затем `interval` добавляет ещё три записи с паузой 250 мс. Каждая новая запись автоматически проходит ту же цепочку.
2. `concatMap` проверяет поля. `onErrorResumeNext` сообщает о некорректной записи и пропускает только её; следующие записи продолжают обрабатываться.
3. `filter` исключает товары с нулевым количеством; `map` вычисляет `price × quantity` через `BigDecimal`.
4. `groupBy` распределяет товары по `supplierId`, а `scan` выдаёт новый накопительный итог поставщика после каждого товара.
5. `subscribeOn(Schedulers.io())` запускает чтение начальных данных в потоке I/O, таймер работает на `Schedulers.single()`, `observeOn(Schedulers.computation())` переносит обработку в вычислительный поток. Имена потоков видны в выводе.
6. С флагом `--backpressure` быстрый `Flowable.range` производит 40 элементов, медленный обработчик тратит 15 мс на каждый. `observeOn(..., 4)` запрашивает элементы ограниченными порциями (`request(n)`); итоговые счётчики показывают, что обработаны все 40 элементов без потерь.

Ожидаемые конечные суммы: **Альфа — 115.00**, **Бета — 60.00**, **Гамма — 30.00**. Нулевая запись не влияет на сумму, ошибочная цена выводится как ошибка данных, но поток продолжается.
